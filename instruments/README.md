# Instruments

> 测量与诊断工件目录。**只提交说明与脚本，不提交大体积工件。**

## 放什么

| 类型 | 例 | 是否入库 |
|---|---|---|
| GPU 捕获 | PIX `.wpix`、RenderDoc `.rdc` | ❌（`artifacts/` 已 gitignore） |
| 性能基线 | 帧时间 CSV、`PresentMon` 记录 | ✅ 小的 CSV 可入库，命名为 `baseline-YYYYMMDD.csv` |
| 色彩测量 | 色度计读数、ΔE 汇总 | ✅ 汇总表格入库，原始数据不入库 |
| 诊断脚本 | 解析捕获、生成报告 | ✅ 入库 |

## 为什么单独一个目录

渲染问题的排查依赖"当时抓到了什么"。把捕获文件、基线数据与**分析结论**放在一起，才能让下一次会话不必重跑一遍实验。

## 约定

1. 每个基线文件必须能被 [Docs/TESTING.md](../Docs/TESTING.md) 的方法复现，文件名带日期。
2. `artifacts/` 下的内容会随时清空，不要在里面放唯一副本。
3. 结论写进文档（`Docs/TESTING.md` 或 ADR），不要只留在抓帧文件里。
